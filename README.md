# Project Introduction

This project is built around the **ESP32-S3-WROOM-1-N16R8** chip, implementing a smart home IoT touch terminal that supports local touch operation and remote real-time data synchronization. The complete solution integrates SPI touchscreen driver, LVGL graphical interface, Wi-Fi provisioning, bidirectional communication with Home Assistant, NVS persistent storage, and OTA remote firmware upgrade functions.

The hardware is equipped with a 3.2-inch 320×240 resistive touch screen (driven by the ILI9341 display controller and XPT2046 touch controller), and the entire firmware is developed based on **ESP-IDF 5.5.2**.

## Core Features

### 1. Hardware Low-Level Drivers

- A layered BSP architecture encapsulates the SPI bus to uniformly manage the ILI9341 display screen and XPT2046 touch controller.
- 8 MB PSRAM is allocated for buffering LVGL frame buffers and large JSON datasets.
- Multi-core task isolation based on FreeRTOS: Core 1 runs the LVGL graphical task, while Core 0 handles all network-related tasks.

### 2. Local Graphical Interface (LVGL v9.3 + GUI Guider)

- GUI code auto-generated by GUI Guider, consisting of 5 interactive pages: Home Page, Wi-Fi Configuration, Home Assistant Device Binding, OTA Upgrade, and System Settings (not yet implemented).
- Supports multi-device control and real-time weather data display with automatic weather icon switching (Sunny / Cloudy / Rainy).

### 3. Wi-Fi Provisioning Module

- Automatic switching between STA and AP modes: The device enables an AP hotspot with a built-in web configuration page when no valid Wi-Fi credentials are stored locally.
- Users can fill in Wi-Fi SSID/password, Home Assistant IP address and access token via the web form; all parameters are automatically saved to NVS non-volatile storage.

### 4. Bidirectional Communication with Home Assistant

Communication is implemented via **HTTP + WebSocket dual protocols**:

- **WebSocket persistent connection**: Enables low-latency bidirectional real-time device control and subscribes to device state changes. No periodic polling is required, which greatly reduces CPU resource consumption.
- **HTTP short connection**: Used during device initialization to fetch all Home Assistant entities in bulk (WebSocket could also fulfill this requirement; HTTP was retained simply to avoid rewriting existing functions).
- cJSON memory heap is redirected to PSRAM to save internal SRAM.

### 5. NVS Persistent Storage

Dedicated NVS namespace stores UI-bound device IDs and Home Assistant connection configurations. All data is retained after power loss and loaded automatically upon device startup.

### 6. OTA Firmware Upgrade

Two upgrade options are provided: local HTTP firmware update and remote version checking & upgrade via Huawei Cloud MQTT service.

### 7. Ultra-Low-Latency State Synchronization

Local touch events uploaded to Home Assistant and device state updates pushed down from Home Assistant are synchronized in real time over WebSocket. The minimum end-to-end latency reaches 60 ms.
